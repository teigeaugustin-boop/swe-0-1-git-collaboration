<h1> Reflection Questions and Responses</h1>

<h4>Where does your code live? Describe (or sketch and include an image of) where your changes exist after each step: after you save the file, after git add, after git commit, after git push, and after your partner runs git pull. At which point can your partner see your work?</h4>

<p>After saving, the code is on my computer. git add stages it, git commit saves it locally, git push sends it to GitHub, and git pull downloads it to my partner’s computer. My partner can see my work on GitHub after I push.</p>

<h4>Your predictions vs. reality. In Round 1, step 5, you each predicted what would happen when Partner B pushed. What did each of you predict, and what actually happened? Using what you know now, explain why git rejected the push. Then explain what git pull did that the push couldn't.</h4>

<p>We predicted Partner B would be able to push, but Git rejected the push because Partner A had already pushed different changes. Git pull brought the new changes to Partner B so they could choose between the two changes and the two versions could be combined properly.</p>

<h4>Resolving a conflict. Pick one of the two conflicts you resolved (Round 1 or Round 2). How did you and your partner decide what to keep? How did you confirm the resolution was correct before pushing?</h4>

<p>We compared both versions of the code and decided together what changes to keep. We checked the final code to make sure it was correct before committing and pushing.</p>

<h4>Getting unstuck. Describe one moment when something didn't work or didn't match what you expected, in the warm-up or while writing the story. What was the exact message or result? What did you check first (for example git status or git remote -v), and what fixed it?</h4>

<p>One major moment we got stuck was a conflict we faced during merging . Initially we panicked because the changes from one partners computer weren't being synced to the others. Though, after navigating through the process and slowing down and working together we figured out the problem was due to us not accepting the commit we wanted to continue with. Finally, after doing so we were able to sync up the changes</p>
